# Конвертация документов в Markdown

Скилл переводит документы в `.md`, выбирая способ чтения под каждый файл, и в конце говорит, что осталось проверить человеку. Работает в Claude Code и в ChatGPT/Codex. Отвечай по-русски.

**Результат для пользователя** — по одному `.md` на документ в выходной папке. Таблицы Excel остаются внутри `.md`, CSV выдаются только по просьбе. Всё служебное (план, журналы, `_ocr.json`, `_ПРОВЕРИТЬ.md`, расшифровки глазами, резервные копии) лежит в отдельной папке запуска и в выдачу не попадает. Исходники только читаются.

**Скилл не делает:** не анализирует содержание; не «исправляет» распознанный текст по смыслу (это ухудшает верность оригиналу); не расшифровывает аудио и видео; не ставит и не обновляет пакеты, модели и программы; не заменяет сверку с оригиналом.

## Платформа и окружение

`<папка навыка>` — каталог этого `SKILL.md`, а не текущая папка. В командах подставляй его абсолютный путь: в Claude Code обычно `~/.claude/skills/convert-docs`, в ChatGPT/Codex — `~/.agents/skills/convert-docs` (в старых установках `~/.codex/skills/convert-docs`).

| Действие | Claude Code | ChatGPT / Codex |
| :-- | :-- | :-- |
| вызов | `/convert-docs <путь>` | `$convert-docs <путь>` в Codex, `@convert-docs` в ChatGPT |
| вопрос пользователю | AskUserQuestion со свободным ответом | инструмент вопроса, если есть (в Codex — `request_user_input_async`), иначе вопрос в ответе |
| долгий OCR | `nohup … &` и инструмент Monitor (шаг 3) | один управляемый shell-процесс с журналом; ждать кода выхода (`write_stdin` по `session_id`) |
| открыть картинку | Read | `view_image` или другой просмотр локальных изображений |
| трудные страницы | субагенты: Agent, `model: "sonnet"` | субагенты, если они разрешены; иначе сам, небольшими пачками |
| временные файлы | scratchpad сессии | `<папка запуска>/tmp` |

Окружения (установка и диагностика — в [УСТАНОВКА.md](УСТАНОВКА.md)):
- `~/Projects/markitdown-local/.venv` — markitdown, pdfplumber, pymupdf4llm, openpyxl;
- `~/ocr-env2` — mlx-vlm, dots.mocr, PyMuPDF, Pillow, pyobjc (Apple Vision);
- poppler (`pdftotext`, `pdffonts`, `pdfinfo`); LibreOffice — для `.doc .rtf .xls .ppt` и Office из сканов;
- необязательно: запасные модели Xiaomi-OCR-0, HunyuanOCR-1.5 (через llama.cpp), GLM-OCR.

Чего-то нет — сказать пользователю, не ставить молча. Окружения в другом месте задаются переменными `CONVERT_DOCS_*` (УСТАНОВКА.md); тогда и в командах ниже подставлять свой путь вместо `~/ocr-env2`.

**Правила сохранности.** Низкоуровневые скрипты (`route.py`, `dots_batch.py`, `postcheck.py`, `merge_eyes.py`) запускать только на рабочей папке запуска, не на пользовательской `_md`. Готовые результаты не перезаписываются: другой текст выдаётся новой версией с суффиксом. Два OCR/GPU-процесса одновременно не запускать (на 24 ГБ это даёт ошибку Metal и испорченные страницы), чужие процессы ради GPU не завершать. Удалять можно только свою папку запуска и только после явного разрешения (шаг 7).

## Цель

1. Путь указан (папка или файл) — работать с ним.
2. Путь не указан, а текущая папка однозначно папка с документами — работать с ней. Домашнюю папку целиком не сканировать.
3. Непонятно — спросить и дождаться ответа.

## Шаг 1. Подготовка и маршрутизация

```bash
python3 "<папка навыка>/scripts/workspace.py" prepare "<цель>" --out "<выходная папка>"
```

Выход по умолчанию — `<цель>/_md` для папки и `_md` рядом с файлом. `prepare` создаёт запуск `~/.local/share/convert-docs/runs/<идентификатор>/`: рабочая папка `documents/`, рядом `plan.json`, журналы и резервные копии. Пути запуска и рабочей папки возьми из вывода команды и держи до конца. Затем `prepare` вызывает `route.py`: офисные файлы и PDF с текстом конвертируются сразу (в рабочую папку), для OCR составляется план. **Это уже обработка, а не предварительный просмотр**; OCR ещё не запускается.

Движок выбирает скрипт, и выбор идёт по проверке результата, а не по типу файла:

| Что | Чем | Почему |
| :-- | :-- | :-- |
| `.docx .pptx .html .epub .csv .txt .msg` | markitdown | структура берётся из разметки файла |
| `.xlsx` | markitdown + служебный CSV на лист | markdown-таблица теряет типы и выравнивание |
| `.doc .rtf .odt`, `.xls .ods`, `.ppt .odp` | мост LibreOffice → markitdown | markitdown их не читает |
| Word/PowerPoint из сканов (текста < 300 знаков, картинки ≥ 30 КБ) | PDF-копия → OCR | в плане `src` — PDF-копия, `orig` — исходник |
| PDF с настоящим текстовым слоем | pdfplumber и pymupdf4llm | остаётся сохранивший больше чисел, при равенстве — больше кириллицы |
| PDF с текстом, внутри которого страницы-сканы (иск с приложениями) | текст — быстрой веткой, сканы — dots.mocr | две строки плана; OCR только страниц `only_pages`, каждая встаёт на своё место в `.md` |
| скан, фото, многостраничный TIFF, PDF с негодным слоем | dots.mocr | читает пиксели |
| фото HEIC с iPhone | JPEG-копия (`sips`) → dots.mocr | PIL HEIC не открывает; в плане `src` — копия, `orig` — исходник |
| аудио, видео | не конвертируются | перечислить как пропущенные |
| архивы и другие форматы | не конвертируются | строка «пропуск» с причиной; показать пользователю (архив — распаковать) |

PDF идёт в OCR, только если: шрифт без ToUnicode (экспорт из CAD) и меньше 200 читаемых букв на страницу; меньше 80 символов на страницу (скан); вшитый OCR-слой негоден (≥ 40 ‰ слов со смесью латиницы и кириллицы; 10–40 ‰ — слой остаётся, в плане пометка «слой с шумом»). Страницы, лежащие боком, быстрая ветка читает с повёрнутой копии; исходник не меняется. Страница PDF с текстом, на которой текста меньше 80 знаков, но есть картинка от 500 × 500 пикселей, считается сканом и идёт в OCR отдельно: раньше такие страницы молча оставались пустыми. **Пересобирать макет там, где буквы уже лежат в файле, нельзя**: OCR теряет ячейки таблиц и числа.

**Office с текстом в OCR не отдаётся**, даже если markitdown споткнулся: в плане `ОШИБКА`, разбираться руками. Если внутри текстового Office есть картинки от 100 КБ или размером со страницу (от 1 Мп: чистый скан в PNG весит меньше 100 КБ), в плане стоит пометка «их текст не распознан». Покажи её пользователю: там может быть печать, схема или скан приложения.

Скрытые файлы (в том числе «двойники» `._имя.pdf`, которые macOS оставляет на флешках и в архивах) и временные `~$…` Office не обрабатываются. Побайтовые дубли конвертируются один раз (оригиналом считается файл с более коротким именем). Содержательные дубли (сжатая копия, вырезка, версия того же скана) хеш не ловит: их исключать повторяемым `--exclude ПОДСТРОКА`. Повторный запуск пропускает готовое, включая `(ПЛОХОЕ КАЧЕСТВО).md`; `--force` — намеренно переделать (результат выйдет новой версией).

Строка `plan.json`: `src`, `rel`, `out`, `ext`, `engine`, `why` и иногда `orig`, `pages`, `note`, `rotated`, `force_ocr`, `csv`, `scan_pages` (у строки быстрой ветки — номера страниц-сканов), `only_pages` (у OCR-строки — какие страницы распознавать). Движки: `markitdown`, `pdfplumber`, `pymupdf4llm`, `ocr`, `дубль`, `пропуск`, `готово`, `ОШИБКА`. Ошибки не скрывать.

## Шаг 2. Согласование — контрольная точка

Сначала поищи в папке готовые расшифровки пользователя. Названы они не как исходники: сопоставляй по числу страниц и первой странице. Найденное в OCR не идёт.

Затем покажи **полный список**, а не сводку: номер, файл, движок, причина, число страниц, пометка, колонка «уже есть расшифровка → файл». Строки «Word/PowerPoint из сканов → OCR» назови отдельно: для `.docx` пользователь OCR не ждёт. PDF с текстом и страницами-сканами показывай одной строкой с пометкой «стр. … — сканы, в OCR». Неизвестное число страниц обозначь явно. Спроси:

> «N файлов без OCR, M в OCR на P страниц (≈ K мин). Правки? Можно назвать номера: "17 и 29 — без OCR", "24 — в OCR". Или "ок".»

Дождись ответа. Если этот объём уже согласован в разговоре, повторно не спрашивай. Правки вноси в `plan.json` (→ OCR: `"engine": "ocr"` и убрать готовый `.md` из рабочей папки); делай ровно то, что ответил пользователь, новых файлов в OCR без его слова не добавляй. Если OCR-файлов нет, переходи к шагу 4.

## Шаг 3. OCR — одним процессом

```bash
~/ocr-env2/bin/python "<папка навыка>/scripts/dots_batch.py" \
  --plan "<папка запуска>/plan.json" > "<папка запуска>/ocr.log" 2>&1
```

**Claude Code.** Запусти команду через `nohup … &` и следи инструментом Monitor; `sleep` в переднем плане и фоновый «ждун» на часы не ставить:

```
command: until ! pgrep -f "[d]ots_batch.py" >/dev/null; do sleep 30; done; echo OCR_DONE
timeout_ms: 1800000
```

Monitor живёт не дольше 30 минут — по истечении переставить. Квадратные скобки в `"[d]ots_batch.py"` обязательны: без них `pgrep -f` находит саму оболочку монитора, и ожидание не кончается никогда. Код выхода после `nohup` не виден, поэтому итог читать в конце журнала.

**ChatGPT / Codex.** Запусти команду одним управляемым процессом и дождись кода выхода; без необходимости не уходи в `nohup … &`, чтобы сохранить возможность дождаться и остановить свой процесс.

Модель загружается один раз, страницы идут по одной. С каждой страницей ([ДВИЖОК.md](ДВИЖОК.md)): Apple Vision читает её для предпросмотра, и снимок почти без текста в OCR не идёт (пометка вместо текста; `--no-skip-empty` отключает); страница, лежащая боком, поворачивается; dots.mocr размечает её, петля обрывается сразу; при битой разметке или петле — второй промпт «просто текст», затем запасные модели по очереди (Xiaomi-OCR-0, HunyuanOCR-1.5, GLM-OCR, если установлены); строки, которые Vision видит, а OCR пропустил, дочитываются по полосам; если ни один движок не дал текста, остаётся резервное чтение Vision; QR-коды дописываются строками `‹QR›`; имена и числа сверяются со вторым чтением Vision, числа — цифра в цифру, и неподтверждённые попадают в пометку `⚠ Не подтверждены вторым чтением`.

Флаги: `--dewarp` (выпрямить фото с сильной трапецией; по умолчанию выключено, потому что на замере теряло цифры в номере счёта — после него сверять числа особенно), `--no-rotate`, `--no-reread`, `--no-qr`, `--no-check`, `--no-skip-empty`, `--second xiaomi,hunyuan15,glm` (порядок запасных; пусто — без них).

**Итог пачки.** Код 0 — все страницы распознаны. Код 1 — что-то не распознано: журнал называет файлы и страницы. Файлы целиком без текста попадают в `<план>.retry.json`, частично нераспознанные страницы идут в чтение глазами. Три файла подряд без результата — остановка: это отказ среды (память, модель), причину выяснить до повтора. Ошибку не превращать в успех и весь набор на другой движок не переключать.

Ориентиры на M4 Pro: A4-скан 35–60 с, фото 30–130 с (с петлёй и запасным движком дольше), снимок без текста около 1 с. На каждую строку журнала отвечать не нужно — только на предупреждения и на конец пачки.

**Про верность оригиналу** (скажи пользователю один раз). dots.mocr, как всякая VLM, иногда «исправляет» опечатки оригинала и подменяет близкие слова, а на рукописи может выдумать связный текст без единого предупреждения. Поэтому рукописные страницы читаются глазами (шаг 5), а сверка Vision показывает, какие имена и числа проверять первыми.

## Шаг 4. Постпроверка — обязательно

```bash
python3 "<папка навыка>/scripts/workspace.py" snapshot "<папка запуска>"
python3 "<папка навыка>/scripts/postcheck.py" "<рабочая папка>"
```

Прочитай `<рабочая папка>/_ПРОВЕРИТЬ.md`. По каждому файлу там:
- **«Прочитать глазами — N стр.»**: петли и обрывы при неуверенном втором чтении; таймауты и сбои; страницы, где Vision видит ≥ 2 строк, которых нет в тексте; дочитанные области (в замере выдумка в 11 случаях из 11); иероглифы и английские фразы в русском тексте; вероятная рукопись. Синие чернила считаются рукописью только там, где её уже видит Vision: подписи и печати иначе дают сотни ложных страниц;
- **«Снимки одного листа»**: на чтение идёт самый резкий, остальные — сверить с ним;
- **«Сверить»**: непроверенные имена и числа, а также страницы, где сама сверка Vision не выполнилась;
- **«Реквизиты не сходятся»** (`requisites.py`): контрольные суммы ИНН, ОГРН, ОГРНИП, СНИЛС, ключ счёта по БИК, сумма цифрами и прописью, доля против процента, разные написания одного реквизита. Это повод открыть оригинал, а не доказательство ошибки;
- **«Пропущено без OCR»** — снимки без текста (фото могут быть доказательствами: назвать пользователю);
- **«ПУСТЫЕ СТРАНИЦЫ»** в разделе файлов — в `.md` есть страница без текста, которую OCR не читал (скан внутри PDF с текстом, пропущенный при прошлом запуске, или пустой лист). Распознать эти страницы или посмотреть оригинал.

**Документ плохого качества** — на ≥ 30 % страниц (не меньше трёх) OCR зациклился, пропустил строки, выдумал текст или понадобился запасной движок. Такой документ стоит в начале `_ПРОВЕРИТЬ.md` и будет выдан как `<имя> (ПЛОХОЕ КАЧЕСТВО).md`. Рукопись сама по себе плохим качеством не считается.

Для старых `_ocr.json` без полей `ink`, `sharp`, `vision_text` сначала: `~/ocr-env2/bin/python -I "<папка навыка>/scripts/page_features.py" "<рабочая папка>"`.

Нет находок Vision — ещё не значит, что текст полон: где Vision сам не читает страницу (размытое или изогнутое фото), отсутствие пометки ничего не доказывает.

## Шаг 5. Рукопись и чтение глазами

**5а. Отбор рукописных страниц — для каждого запуска с OCR.** Постпроверка ловит рукопись не целиком: печатный бланк с рукописными дописками (лист назначений, чек-лист, коагулограмма) она пропускает, а на тесте именно там были ошибки в датах, названиях препаратов и пометках «отменено». Миниатюры дёшевы, поэтому смотреть их нужно всегда, а не только когда постпроверка нашла рукопись:

```bash
~/ocr-env2/bin/python -I "<папка навыка>/scripts/contact_sheet.py" --plan "<папка запуска>/plan.json" "<временная папка>/sheets"
```

Листы 4 × 3 охватывают все распознанные страницы всех документов запуска, поворот берётся из их `_ocr.json`, снимки без текста пропускаются. Подпись миниатюры «Д<k>·<стр>», расшифровка «Д<k>» — в `sheets/_ЛЕГЕНДА.md`. Для одного документа и части страниц: `contact_sheet.py "<исходник>" "<папка>" --ocr-json "<рабочая папка>/…/<имя>_ocr.json" --pages 1-30`. Без `--ocr-json` листы строятся без поворота, потому что JSON лежит в папке запуска, а не рядом с исходником.

Просмотри листы (в Claude Code — субагент: Agent, `model: "sonnet"`, `effort: "low"`; на замере 26 рукописных страниц из 26 без лишних). Назови страницы с рукописным текстом или рукописными значениями (даты, числа, названия, пометки в таблицах); одни подписи и номер листа в углу не считаются. Сомнительные страницы с рукописными значениями в таблицах тоже идут на чтение. Добавь найденное к «Прочитать глазами». Не объявляй отбор законченным, пока не просмотрены все листы.

**5б. Чтение глазами.** Страницы из «Прочитать глазами» и шага 5а OCR не возьмёт никаким движком. Их читает модель по картинке, но **не в основном контексте**: картинки и расшифровки быстро съедают его.

1. Раздай страницы субагентам пачками до 10 (пачки можно параллельно). В Claude Code: Agent, `model: "sonnet"`, `effort: "high"` — на трудной рукописи это заметно точнее `medium`, а более дорогая модель не точнее. В ChatGPT/Codex — доступную модель с просмотром изображений. В задании: `<папка навыка>`, исходник (для Office из сканов — PDF из поля `src` в `_ocr.json`, не `.docx`), номера страниц, поворот `rotation` каждой из `_ocr.json`, папка `.md` в рабочей папке и строка «Порядок работы — в `<папка навыка>/ЧТЕНИЕ-ГЛАЗАМИ.md`». Субагент пишет только `_ЧТЕНИЕ-*` для своих страниц и возвращает короткий список. Если субагентов нет — читай сам небольшими пачками; если нет и просмотра картинок — оставь страницы непроверенными и прямо скажи об этом.
2. Картинки в основном контексте не открывать; от субагентов взять только список записанных файлов и страниц, где много `[?]`.
3. До 20 страниц делай без отдельной просьбы, больше — покажи список и спроси. Документ плохого качества целиком не раздавай автоматически: назови число страниц и спроси. Разрешение на весь документ включает и его проблемные страницы — второй раз не спрашивай.
4. Когда все субагенты закончили, объедини:

```bash
python3 "<папка навыка>/scripts/workspace.py" snapshot "<папка запуска>"
python3 "<папка навыка>/scripts/merge_eyes.py" "<рабочая папка>" --keep
python3 "<папка навыка>/scripts/postcheck.py" "<рабочая папка>"
```

`merge_eyes.py` заменяет раздел `## Страница N` расшифровкой с пометкой «✎ Прочитано глазами» и ставит странице `eyes` в `_ocr.json`; повторная постпроверка проверит реквизиты и на прочитанных страницах.

**Правка по картинке.** Реквизит, не прошедший проверку, сверяй по картинке. Ошибка чтения — исправить число; так в самом документе — оставить и дописать сразу после числа `[так в оригинале; …]` (юристу эта ошибка документа важна); край кадра — `[обрезано краем снимка]`; не разобрать — `[?]`. Под страницей строка `> ✎ Исправлено по картинке <дата>: …`, журнал правок `_ИСПРАВЛЕНИЯ-<дата>.md` — в рабочей папке. После исправления повторная постпроверка уже не перечисляет в «сверить» прежнее значение, которого на странице больше нет. Цифры под контрольную сумму не подгонять. Если находка называет «проходящий проверку» вариант из того же документа, подставлять его без сверки с картинкой нельзя.

Рукопись и после чтения глазами — материал для поиска и понимания, а не для цитирования без сверки с оригиналом.

## Шаг 6. Выдача

```bash
python3 "<папка навыка>/scripts/workspace.py" publish "<папка запуска>"
```

`--csv` добавляет CSV листов Excel — только по просьбе пользователя. `publish` снимает резервную копию, ещё раз запускает постпроверку и копирует в выходную папку только основные `.md` из плана, с той же структурой подпапок: `<выходная папка>/<подпапка>/<имя>/<имя>.md`. Документ плохого качества получает предупреждение в начале и имя `(ПЛОХОЕ КАЧЕСТВО)`. Существующий файл не перезаписывается: одинаковый пропускается, отличающийся выдаётся с суффиксом версии.

`publish` откажет (код 1), если есть невставленные `_ЧТЕНИЕ-*`, OCR не завершён или число страниц расходится с планом, либо остались нераспознанные страницы, не прочитанные глазами. Такой документ нельзя объявлять готовым. `publish` проверяет техническую завершённость; что проблемные места сверены, обеспечиваешь ты.

**Ответ пользователю:** ссылки на итоговые `.md` (полные пути); сколько готово из скольких, что упало и почему; что осталось проверить — поимённо, с числом страниц «прочитать глазами» и «сверить»; **документы плохого качества — отдельно и капслоком** (фамилии, цифры, даты и цитаты из них — только по оригиналу); снимки, пропущенные без OCR, — одной строкой; что прочитано глазами. Различай распознавание, сверку проблемных мест и построчную вычитку всего документа. Служебные файлы не предлагай как результат, безошибочность не обещай. Напомни: ни одну цифру, фамилию и цитату из OCR нельзя ставить в процессуальный документ без сверки с оригиналом.

## Шаг 7. Приёмка и очистка

```bash
python3 "<папка навыка>/scripts/workspace.py" cleanup-plan "<папка запуска>"
```

Команда ничего не удаляет: проверяет выданные файлы по SHA-256 и пишет полный список содержимого запуска в `cleanup-plan-*.json`. Вместе с результатом назови полный путь папки запуска и предложи удалить её целиком. Объясни: после приёмки рабочие данные не нужны, обработку можно повторить из исходника, но промежуточные версии после удаления не восстановить. Предложи ответить: «Результат принят, указанную служебную папку удалить».

Простое «принято» — не разрешение на удаление. Только после явного разрешения на этот путь:

```bash
python3 "<папка навыка>/scripts/workspace.py" cleanup "<папка запуска>" \
  --manifest "<папка запуска>/cleanup-plan-<идентификатор>.json" \
  --approved-path "<точный путь, согласованный пользователем>"
```

Команда снова сверяет результат и список и удаляет только эту папку запуска. Если что-то изменилось, остановись и выясни причину; отказ не обходи. Другие запуски и старые папки пользователя в очистку не входят.
