# convert-docs

Скилл для ИИ-агента, который переводит папку документов в Markdown на Mac: Word, Excel, PowerPoint, PDF, сканы и фотографии. Распознавание идёт **локально**: документы не уходят в облачные OCR-сервисы. Агент (Claude Code или ChatGPT/Codex) ведёт процесс: показывает план, запускает распознавание, разбирает сомнительные страницы и в конце называет, что человеку нужно сверить с оригиналом.

Сделан для юридической работы с русскими документами (договоры, выписки, материалы дел, рукописные объяснения), но годится для любых документов.

## Что он делает

| Вход | Обработка | Выход |
|---|---|---|
| DOCX, XLSX, PPTX, HTML и другие офисные файлы | собственная разметка файла через markitdown; старые DOC, XLS, PPT — через LibreOffice | Markdown (CSV листов Excel — по просьбе) |
| PDF с настоящим текстовым слоем | pdfplumber и pymupdf4llm, остаётся вариант, сохранивший больше чисел; страницы боком выправляются | Markdown без OCR |
| фото HEIC с iPhone | JPEG-копия средствами macOS и OCR | Markdown |
| сканы, фото, многостраничный TIFF, PDF с битым шрифтом или негодным OCR-слоем | локальная модель dots.mocr: поворот страницы, остановка зацикливания, запасные модели, дочитывание пропущенных строк, QR-коды | Markdown |
| Word или презентация, собранные из сканов | PDF-копия и OCR; исходник не меняется | Markdown |
| PDF с текстом, в который вшиты сканы (иск с приложениями) | текстовые страницы — из текстового слоя, страницы-сканы — OCR | один Markdown, каждая страница на своём месте |

Каждую распознанную страницу независимо читает Apple Vision: имена и числа, которые второе чтение не подтвердило, помечаются. Постпроверка ищет пустые страницы, петли, пропуски, выдумку, рукопись и реквизиты с неверной контрольной суммой (ИНН, ОГРН, СНИЛС, счёт по БИК, сумма цифрами и прописью). Миниатюры всех распознанных страниц просматриваются, чтобы найти рукописные дописки на печатных бланках (листы назначений, чек-листы): их агент тоже дочитывает по картинке, как и страницы, которые не берёт ни один движок.

**Результат:** один `.md` на документ в выходной папке. План, журналы и служебные файлы лежат отдельно, в `~/.local/share/convert-docs/runs/`. Исходники не меняются, готовые результаты не перезаписываются, служебная папка удаляется только с разрешения пользователя.

Сканы и особенно рукопись требуют сверки. Пометки показывают, где проверять, но не доказывают, что текст безошибочен. Цифры, фамилии и цитаты для важных документов сверяйте с оригиналом.

## Где работает

- **Claude Code** — `/convert-docs <папка>`.
- **Codex** (CLI, расширение IDE) — `$convert-docs <папка>`.
- **ChatGPT** (настольное приложение, локальная работа с папкой) — `@convert-docs <папка>`. Нужен локальный режим с доступом к файлам и командам: облачный чат без подключения к компьютеру не видит ни документов, ни моделей.

Один и тот же `SKILL.md`; различия платформ (вопросы пользователю, ожидание долгого OCR, просмотр картинок, субагенты) описаны в нём таблицей.

## Что нужно

- Mac на Apple Silicon. Проверено на Mac mini M4 Pro, 24 ГБ, macOS 26, Python 3.12.
- Homebrew, Python 3.12, poppler; LibreOffice — для старых форматов Office.
- Около 1,3 ГБ на окружения и 4,4 ГБ на модель dots.mocr. Запасные модели (Xiaomi-OCR-0, GLM-OCR, HunyuanOCR-1.5) необязательны и занимают ещё 1–2 ГБ каждая.
- Интернет — только при установке пакетов и первом скачивании весов.

Скорость на M4 Pro: страница скана A4 — 35–60 с, фото — 30–130 с, офисные файлы и PDF с текстом — секунды.

## Установка

Подробно, с проверками и разбором сбоев, — в [УСТАНОВКА.md](УСТАНОВКА.md). Коротко:

```bash
git clone https://github.com/supaboris-source/convert-docs.git ~/Projects/convert-docs
cd ~/Projects/convert-docs
brew install python@3.12 poppler

/opt/homebrew/bin/python3.12 -m venv ~/Projects/markitdown-local/.venv
~/Projects/markitdown-local/.venv/bin/pip install -r requirements-light.txt

/opt/homebrew/bin/python3.12 -m venv ~/ocr-env2
~/ocr-env2/bin/pip install -r requirements-ocr.lock.txt
HF_HUB_DISABLE_XET=1 ~/ocr-env2/bin/hf download mlx-community/dots.mocr-8bit

./install.sh          # скилл для найденных программ: Claude Code и/или ChatGPT/Codex
~/ocr-env2/bin/python -I ~/.claude/skills/convert-docs/scripts/selftest.py   # или ~/.agents/skills/…
```

Есть ещё две проверки (в `tests/`, в установку не входят): `test_logic.py` — логика без GPU за несколько секунд (коды выхода, отказ выдачи, очистка, сканы внутри PDF, установщик); `make_hard_set.py` + `check_hard_set.py` — 18 трудных файлов с известным текстом (сканы боком и вверх ногами, фото таблиц, Word и презентации из сканов, HEIC, PDF с испорченным OCR-слоем, архив, аудио) и автоматическая сверка всех контрольных значений.

Самопроверка собирает вымышленные документы (текстовый PDF, скан, фото, двухстраничный TIFF, таблица, PDF «текст — скан — текст»), проводит их всей цепочкой примерно за четыре минуты GPU и пишет «всё работает» или что сломалось.

## Как это устроено

```
SKILL.md              порядок работы агента (общий для Claude Code и ChatGPT/Codex)
ЧТЕНИЕ-ГЛАЗАМИ.md     порядок работы субагента, читающего трудные страницы по картинке
ДВИЖОК.md             устройство OCR, формат _ocr.json, пороги, замена движка
УСТАНОВКА.md          установка, версии, самопроверка, сбои
agents/openai.yaml    название и описание для интерфейса ChatGPT/Codex
install.sh            раскладка скилла по папкам программ
scripts/
  workspace.py        запуск: служебная папка, выдача итоговых .md, очистка по разрешению
  route.py            маршрутизация и быстрая ветка (markitdown, pdfplumber, pymupdf4llm)
  dots_batch.py       OCR по плану одной загрузкой модели
  dots_engine.py      движок: dots.mocr, запасные модели, поворот, петли, дочитывание
  crosscheck.py       второе чтение Apple Vision: сверка имён и чисел
  postcheck.py        постпроверка и список _ПРОВЕРИТЬ.md
  requisites.py       контрольные суммы и согласованность реквизитов
  merge_eyes.py       вставка расшифровок глазами в документ
  contact_sheet.py    листы миниатюр для отбора рукописных страниц
  selftest.py         самопроверка всей цепочки
  …                   ориентация, выпрямление фото, QR, признаки страницы
```

Версии пакетов закреплены в `requirements-ocr.lock.txt` и `requirements-light.txt`; модели после скачивания грузятся только из локального кэша.

## Ограничения

- Только macOS на Apple Silicon: OCR работает на MLX, второе чтение — на Apple Vision.
- Рукопись локальная модель читает плохо и может выдумать связный текст: такие страницы агент читает по картинке, а человек сверяет с оригиналом.
- Зачёркивание OCR не передаёт: зачёркнутое (например, отменённое назначение) выглядит как обычный текст. На страницах, прочитанных глазами, оно помечается `~~…~~`.
- Картинки без текста (схемы, фото помещений) в OCR не идут: в `.md` попадает только то, что прочитал Apple Vision. Их нужно смотреть как изображения.
- Не ловятся: неверный номер с верной контрольной суммой, одинаковый во всём документе; цифры вне реквизитов, которые второе чтение подтвердило с той же ошибкой.
