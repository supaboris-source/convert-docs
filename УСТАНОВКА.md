# Установка convert-docs (macOS, Apple Silicon)

Шаги проверены так: оба окружения собраны с нуля в пустом домашнем каталоге из файлов `requirements-*.txt` рядом, на синтетическом тестовом наборе (`scripts/make_test_set.py`) прогнаны маршрутизатор, OCR и постпроверка. Рабочая машина: Mac mini M4 Pro, 24 ГБ, macOS 26. На других Mac и версиях macOS не проверялось. Шаги про llama.cpp и HunyuanOCR-1.5 проверены на рабочей машине, но не с нуля.

Устройство OCR и замена движка описаны в [ДВИЖОК.md](ДВИЖОК.md).

## Что получится

| Что | Где | Зачем |
| :-- | :-- | :-- |
| лёгкое окружение | `~/Projects/markitdown-local/.venv` | офисные форматы, PDF с текстовым слоем |
| окружение OCR | `~/ocr-env2` | dots.mocr, запасные модели, Apple Vision (pyobjc) |
| модели | кэш Hugging Face (`~/.cache/huggingface`) и `~/models` | веса OCR, качаются один раз |
| скилл для Claude Code | `~/.claude/skills/convert-docs` | вызов `/convert-docs <папка>` |
| скилл для ChatGPT и Codex | `~/.agents/skills/convert-docs` (или прежний `~/.codex/skills/convert-docs`, если он уже есть) | вызов `@convert-docs` в ChatGPT, `$convert-docs` в Codex |
| рабочие запуски | `~/.local/share/convert-docs/runs` | план, журналы, служебные файлы каждой обработки |

Другие места окружений и моделей задаются переменными: `CONVERT_DOCS_LIGHT_VENV`, `CONVERT_DOCS_OCR_VENV`, `CONVERT_DOCS_MODELS`, `CONVERT_DOCS_HOME` (папка запусков), `DOTS_MODEL` (путь к снапшоту dots.mocr). Без них действуют пути из таблицы. Команды в `SKILL.md` написаны для путей по умолчанию.

Ниже `REPO` — папка, куда скачан репозиторий, например `~/Projects/convert-docs`.

## 1. Системное

Homebrew (если его нет) ставится одной командой с сайта https://brew.sh. Дальше:

```bash
brew install python@3.12 poppler
```

- Нужен именно Python 3.12: версии пакетов в `requirements-*.txt` собраны под него.
- `poppler` даёт команды `pdftotext`, `pdfinfo`, `pdffonts`; без них маршрутизатор не работает.
- Необязательно, для старых форматов `.doc .rtf .odt .xls .ppt` и Word из сканов: `HOMEBREW_NO_INSTALL_UPGRADE=1 HOMEBREW_NO_AUTO_UPDATE=1 brew install --cask libreoffice` (переменные не дают тронуть закреплённые пакеты). Проверено: `.doc`/`.rtf` с таблицей и кириллицей, `.xls`, Word из 5 сканов и его `.doc`-копия.
- Необязательно, для запасного движка HunyuanOCR-1.5: `brew install llama.cpp` (команда `llama-mtmd-cli`, проверена версия 0.4.1). Без него этот движок не включается, остальное работает.
- Рекомендуется: `brew pin python@3.12 poppler` — защищает от обновления «за спиной». Окружения привязаны к Homebrew-Python, и его обновление может их сломать.

Проверка: `/opt/homebrew/bin/python3.12 --version` и `pdftotext -v` отвечают без ошибки.

## 2. Лёгкое окружение (около 45 секунд)

```bash
mkdir -p ~/Projects/markitdown-local
/opt/homebrew/bin/python3.12 -m venv ~/Projects/markitdown-local/.venv
~/Projects/markitdown-local/.venv/bin/pip install -r "$REPO/requirements-light.txt"
```

Закреплены `markitdown 0.1.5`, `pdfplumber 0.11.9`, `pymupdf4llm 1.28.2`, `openpyxl 3.1.5` и всё, что они тянут. Версии не обновлять без нужды.

## 3. Окружение OCR (около 2 минут на пакеты, 1,1 ГБ, и около 8 минут на модель, 4,4 ГБ)

```bash
/opt/homebrew/bin/python3.12 -m venv ~/ocr-env2
~/ocr-env2/bin/pip install -r "$REPO/requirements-ocr.lock.txt"   # точные версии, с которыми всё проверено
HF_HUB_DISABLE_XET=1 ~/ocr-env2/bin/hf download mlx-community/dots.mocr-8bit
```

Запасные модели (необязательно; включаются только на странице, где dots.mocr зациклился или упёрся в лимит):

```bash
HF_HUB_DISABLE_XET=1 ~/ocr-env2/bin/hf download SeerRay-Lab/Xiaomi-OCR-0        # 1,7 ГБ bf16
~/ocr-env2/bin/python -m mlx_vlm.convert --hf-path SeerRay-Lab/Xiaomi-OCR-0 --mlx-path ~/models/Xiaomi-OCR-0-mlx-8bit -q --q-bits 8   # секунды; движок ищет модель по этому пути
HF_HUB_DISABLE_XET=1 ~/ocr-env2/bin/hf download mlx-community/GLM-OCR-bf16      # 2,2 ГБ
HF_HUB_DISABLE_XET=1 ~/ocr-env2/bin/hf download prithivMLmods/HunyuanOCR-1.5-GGUF-Updated HunyuanOCR.Q8_0.gguf HunyuanOCR.mmproj-f16.gguf --local-dir ~/models/HunyuanOCR-1.5-gguf   # 1,6 ГБ, нужен llama.cpp
```

- Версии закреплены (`mlx-vlm 0.7.8`, с ним `mlx 0.32.4`, `transformers 5.19`).
- `pyobjc-framework-Vision` и `-Quartz` нужны для ориентации страниц, выпрямления фото (`--dewarp`), сверки имён и чисел вторым чтением, проверки полноты, резервного чтения и QR-кодов. Без них скилл работает, но эти проверки молча отключаются. Орфографию для проверки полноты даёт `AppKit` из `pyobjc-framework-Cocoa`; без него дочитывание срабатывало бы на рукописи и печатях зря.
- `HF_HUB_DISABLE_XET=1` обязателен: через xet загрузка стопорится и при перезапуске начинается с нуля, по обычному HTTP докачивается. Оборвалась — повторить ту же команду.
- Память: около 7 ГБ на процесс; Xiaomi-OCR-0 при вызове добавляет 2,5 ГБ; HunyuanOCR-1.5 работает отдельным процессом на время вызова. Две GPU-задачи одновременно не запускать: на 24 ГБ это давало ошибку Metal «Insufficient Memory» и испорченные страницы.
- Лицензии моделей — в их карточках на Hugging Face. У HunyuanOCR (Tencent Hunyuan Community License) есть территориальные ограничения: она не распространяется на ЕС, Великобританию и Южную Корею.

Проверка запасных движков:

```bash
~/ocr-env2/bin/python -c "import sys; sys.path.insert(0, '$REPO/scripts'); import dots_engine as d; print({k: d.second_available(k) for k in ('xiaomi', 'hunyuan15', 'glm')})"
```

Для установленного движка ответ `True`. HunyuanOCR-1.5 требует `llama-mtmd-cli` (в PATH или каталогах Homebrew) и оба GGUF.

## 4. Скилл

```bash
cd "$REPO" && ./install.sh            # для всех найденных программ: Claude Code и/или ChatGPT/Codex
./install.sh --claude                 # только Claude Code
./install.sh --codex                  # только ChatGPT/Codex
./install.sh --dry-run                # показать, что будет сделано
```

Установщик копирует только файлы скилла: пакеты, модели и программы он не ставит. Прежняя установка не удаляется, а переносится в `~/.local/share/convert-docs/skill-backups/`. Переносится вне папки скиллов, чтобы не появилось двух скиллов с одним именем. Для ChatGPT/Codex скилл ставится в `~/.agents/skills/convert-docs`; если уже есть прежний `~/.codex/skills/convert-docs`, обновляется он.

После установки: в Claude Code — `/convert-docs <папка>`; в Codex — `$convert-docs <папка>` (если скилл не виден, перезапустить Codex); в настольном ChatGPT — раздел Skills и `@convert-docs <папка>` в локальной работе с папкой.

## 5. Проверка

Полная самопроверка (около пяти минут GPU, другие модели в это время не запускать):

```bash
~/ocr-env2/bin/python -I ~/.claude/skills/convert-docs/scripts/selftest.py      # или из ~/.agents/skills/…
```

Она делает тестовый набор во временной папке (шесть файлов, в том числе PDF «текст — скан — текст») и проводит его тем же путём, что и агент: `workspace.py prepare` → `dots_batch.py` → `postcheck.py` → `workspace.py publish`. Итог — «всё работает» или список поломок; при поломке временная папка остаётся для разбора, `--keep` оставляет её и при успехе.

Проверки для разработки (в репозитории, в установку не входят):

```bash
~/ocr-env2/bin/python -I "$REPO/tests/test_logic.py"          # логика без GPU, секунды
~/Projects/markitdown-local/.venv/bin/python "$REPO/tests/make_hard_set.py" ~/Desktop/сложный-набор/набор
# затем прогнать ~/Desktop/сложный-набор/набор скиллом и сверить:
python3 "$REPO/tests/check_hard_set.py" ~/Desktop/сложный-набор <папка запуска> <папка выдачи>
```

Тот же набор можно прогнать через агента:

```bash
~/Projects/markitdown-local/.venv/bin/python "$REPO/scripts/make_test_set.py" ~/Desktop/тест-OCR
```

и попросить: `/convert-docs ~/Desktop/тест-OCR` (или `$convert-docs` / `@convert-docs`). Ожидаемо (M4 Pro):

| Файл | Движок | Время | Что должно быть в `.md` |
| :-- | :-- | :-- | :-- |
| 01_договор_с_текстом.pdf | pdfplumber | 1 с | все 11 контрольных значений |
| 02_договор_скан.pdf | dots.mocr | около 41 с | все 11 контрольных значений |
| 03_договор_фото.jpg | dots.mocr | около 52 с | все 11 (с `--dewarp` 10 из 11: в номере счёта пропадает ноль, `_ПРОВЕРИТЬ.md` помечает это число) |
| 04_расчёт.xlsx | markitdown | 1 с | таблица (CSV — по просьбе) |
| 05_договор_tiff.tif | dots.mocr | около 45 с (две страницы) | обе страницы, на каждой все 11 значений |
| 06_иск_со_сканом.pdf | pdfplumber + dots.mocr (стр. 2) | около 42 с | три страницы; на второй (скан) все 11 значений, с пометкой «Страница без текстового слоя» |

Контрольные значения: `17/2026`, `125 000,00`, `15 000,00`, `40 000,00`, `70 000,00`, `7700000001`, `40702810000000000017`, `044525999`, `0,1%`, `Ромашка`, `Сидоров`.

Что бывает при первом запуске:
- первый вызов markitdown после установки медленный (16 с против 0,4 с на повторе); однажды `.xlsx` получил `ОШИБКА` и прошёл со второго раза — запустить ту же команду ещё раз, готовое пропускается;
- постпроверка может назвать «почти пусто» небольшую таблицу (меньше 300 байт) — это не брак;
- OCR в таблице может склеить соседние столбцы; цифры сохраняются, структуру таблицы проверять глазами.

## 6. Обновления: что закреплено и как проверять

Обновление библиотек — главный источник тихих поломок. Поэтому:
- **brew:** `python@3.12`, `poppler` и `llama.cpp` лучше закрепить `brew pin`, тогда `brew upgrade` их пропустит;
- **пакеты:** `requirements-ocr.lock.txt` и `requirements-light.txt` — точные версии; `pip install -U` в окружениях не делать;
- **модели** грузятся только из локального кэша (`local_files_only`), их снапшоты записаны в шапке `requirements-ocr.lock.txt`.

После любого обновления (macOS, Xcode/CLT, brew, пакеты, модели) — `selftest.py`. Намеренное обновление: `brew unpin <имя> && brew upgrade <имя>`, затем selftest, затем `brew pin <имя>`; для пакетов — обновить, прогнать selftest и перезаписать lock (`pip freeze`). Откат окружения: удалить `~/ocr-env2` и повторить раздел 3 — lock вернёт те же версии.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
| :-- | :-- | :-- |
| `pdftotext: command not found` | нет poppler | `brew install poppler` |
| `route.py` пишет «НЕТ markitdown» | не создано лёгкое окружение или оно в другом месте | раздел 2 или переменная `CONVERT_DOCS_LIGHT_VENV` |
| dots.mocr не грузится, `ModuleNotFoundError` | не то окружение | запускать `~/ocr-env2/bin/python`, не системный |
| в журнале OCR нет `ROTATED` и `сверить:` даже на фото; нет «дочитывание областей: Vision» | в окружении нет pyobjc (или запуск с `--no-reread`) | `~/ocr-env2/bin/pip install pyobjc-framework-Vision pyobjc-framework-Quartz` |
| после текста страницы длинный блок «Дочитано по областям» с мусором | нет AppKit (орфофильтр молча выключен) или страница рукописная | `~/ocr-env2/bin/python -c "import AppKit"` должен отвечать без ошибки; страницу смотреть глазами |
| страница 60–120 с с пометкой `LOOP_DETECTED` | модель зациклилась, петля оборвана, страница ушла на второй промпт или движок | нормально; страница будет в `_ПРОВЕРИТЬ.md` |
| загрузка модели стоит на нескольких ГБ | xet | повторить с `HF_HUB_DISABLE_XET=1` |
| в журнале нет `hunyuan15` среди запасных движков | нет `llama-mtmd-cli` в PATH или нет двух GGUF | `brew install llama.cpp`, скачать GGUF; включить вручную: `DOTS_SECOND=xiaomi,hunyuan15,glm` |
| `dots_batch.py` завершился с кодом 1 | часть страниц не распознана (таймаут, сбой) или три файла подряд упали | журнал называет страницы; целиком упавшие файлы — в `<план>.retry.json`; при трёх подряд искать отказ среды (память, модель) |
| `publish` отказывает | не объединено чтение глазами, OCR не завершён или есть нераспознанные страницы | сообщение называет файл и страницы; доделать и повторить |
| selftest пишет, что не удалось проверить занятость GPU | среда агента не даёт списка процессов | запустить selftest в обычном Терминале |

Если чего-то не хватает, скрипт скажет прямо и не станет ставить молча.
